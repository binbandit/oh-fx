# Composer, prompt history, and `@` mentions

- Prompt history lives in `$XDG_DATA_HOME/oh-fx/history.jsonl`, guarded by `history.lock` beside it, where upstream uses `~/.fx/history.jsonl` and `~/.fx/history.lock`. Its records, size caps, compaction, deduplication, and permissions follow upstream.
- The `@` file index cache lives in `$XDG_CACHE_HOME/oh-fx/file-index/<sha256 of the indexed roots>.idx`, where upstream uses `~/.fx/file-index`. Its format, size caps, integrity check, and permissions follow upstream.
- Prompt history records hold the prompt as a JSON string. Upstream writes a prompt that is not valid UTF-8 as a `{"encoding":"base64","data":…}` object; the composer holds only UTF-8 text, so oh-fx never writes that form, and a record that uses it is skipped as malformed when the history is read and dropped when it is compacted. The history file is opened without blocking, so a FIFO in its place fails as `DurablePathUnsafe` where upstream's open waits for a writer. Skipped records and failed appends write no trace lines, since oh-fx has no trace log yet. `prompt_history.enabled` is read from `settings.json` when the interactive session starts, and the `/settings` menu's `Prompt history` row switches it as upstream's does: off stops recording at once and then saves, and on saves first and starts recording only once the save succeeds. History that starts off loads no entries, so turning it on records new prompts without bringing back older ones until the next launch, as upstream's does.
- The `@` file index covers the workspace and then each active additional directory, whose entries show absolute paths, as upstream's does. A path indexed under the workspace is not listed again under an additional directory inside it. When `/workspace` changes the active directories, through a command or the availability refresh it runs before listing them or opening its menu, the index rebuilds for the new scope in the background, as upstream's does, and `@` neither offers rows from the old scope while it rebuilds nor accepts a row it showed before the change, as upstream's picker drops them when the new scope is installed. A file index cache that cannot be read or written writes no trace line, since oh-fx has no trace log yet. The index belongs to the workspace, not the session, so `/clear`, `/new`, `/reset`, and a resumed session keep using it, as upstream does, and a prompt keeps its `@` mentions as typed in the saved session and in its replay. A session that ends while the index is still listing files does not wait for git, whose listing oh-fx cannot cancel, and that scan writes no cache; a cache write already under way finishes first. Upstream cancels the listing and waits for its loader.
- The composer draws neither C1 controls nor the line separator and bidi controls that rows escape, so a draft holding one keeps the cursor where the layout puts it: the layout measures them as taking no cells, as upstream's does, and upstream writes them to the terminal. They stay in the draft and reach the model.
- The composer's copy and cut shortcuts, Super-C and Super-X, put the selection on the system clipboard through upstream's command, `pbcopy` on macOS and `xclip -selection clipboard` on Linux, and do nothing without a selection or on other systems, as upstream does; cut then deletes the selection only once the command has exited successfully. The command runs on a background thread, so the shell keeps reading keys and drawing while it runs, where upstream waits for it on its UI thread without a time limit. A command still running 5 seconds after it started, the limit upstream gives its clipboard file copy, is killed and counts as failed. A cut deletes the selection only if the composer still selects the same range holding the same text when the command finishes, so a key that changes the selection or its text first keeps the draft as it is, as a failed copy does. One command runs at a time: a copy or cut requested while one runs waits for it, a later request replaces the waiting one, and leaving the shell restores the terminal and stops the agent, then waits for both. A failed copy leaves the draft and the selection unchanged and shows nothing, as upstream does; upstream also writes the reason to its trace log, which oh-fx does not have yet.
- Replacing a selection with typed or pasted text, and deleting to the start or end of the line with Ctrl+U or Ctrl+K, end the vertical motion in progress, as every other edit does, so the next Up or Down keeps the column the cursor has after the edit. Upstream keeps the column recorded before the replacement or the line deletion, so after a selection made with Shift+Up or Shift+Down is replaced or deleted that way, or after Up or Down onto a shorter line is followed by Ctrl+U or Ctrl+K, the next Up or Down lands in that earlier column.
