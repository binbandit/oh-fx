# Model, Fast mode, settings, and status line commands

- `/model` without an argument, Enter on a slash completion that resolves to it, and Ctrl+P open upstream's model menu in the footer, and typing `/model ` opens its inline model, effort, and mode columns, with upstream's rows, vendor tabs, filtering, keys, catalog notes, and footer precedence: the help menu, then the model menu, then the skills menu, then the model column, then the provider column, then the `@` picker. The menu lists the Codex catalog for the Codex subscription and a custom connection's `models` with their `model_metadata` facts; a custom connection advertises no efforts or Fast mode, so choosing one of its models applies it at once. oh-fx asks for the catalog the first time a picker needs it in a session, and again when the menu opens or Tab opens the column after a failed load, where upstream warms its model cache at launch and retries a failed load a second later, so a launch that never opens a picker fetches nothing. A Codex catalog fetched for capabilities, a picker, or a `/model` query is kept for the session. As upstream, only HTTP 429, 500, 502, 503, and 504 answers and transport failures count as retryable, with upstream's `retry /model` notes, and every other failure reads `Unable to load models.`. The menu is drawn between blank rows, as the skills menu is, and the columns between dividers, as the `@` picker is. Ctrl+P keeps the draft aside, with its pasted blocks, undo history, and prompt-history position, until the menu and the columns it leads to close, as upstream's does. The session picker, the help menu, the model menu, and the skills menu never share the footer: while the session picker, the help menu, the settings menu, or the status line menu is open, Ctrl+P does nothing and `/model `, `/provider `, `/login `, and `/setup ` open no column. A `$` typed or pasted while the model menu is open or its columns hold a lent draft opens no `$` mention menu, and a mention menu hidden because no skill matches leaves Ctrl+P and the `/model ` columns working. Commands run on the agent thread, so a `/help`, `/skills`, `/provider`, `/resume`, or Super+R reply can arrive after another of them, `/settings`, or `/statusline` opened its menu or Ctrl+P lent the draft; such a reply then leaves the open one and the draft as they are instead of opening over them, where upstream runs those commands before it reads the next key.
- `/provider` (`/setup`) and `/login` put `/provider ` or `/login ` in the composer, and that prefix, or `/setup `, typed by hand opens upstream's inline provider column with upstream's keys: arrows move, Tab completes, typing filters, Enter or Right at the end of the text switches, and Esc hides the column until the command is typed again. Tab, Enter, and Right take the highlighted provider, and a name typed exactly is highlighted as it is typed, so connections whose names share a prefix, such as `local` and `local-alt`, can each be chosen. Upstream lets an exactly typed name win over the highlight; its fixed provider names never share a prefix, so the two only differ for configured connections. While a turn or compaction runs, or prompts wait, the column is hidden, arrows and Tab do nothing, Space and Right edit the text, and Enter and the commands report upstream's busy notice, as upstream limits them. The column lists `codex` and every connection under `providers`, in settings order, as the commands read them from the settings file, and marks the active one `current`. Upstream lists `vercel`, `codex`, and `grok` and has no row for a configured provider; the `vercel` and `grok` rows, and the sign-in method, team, and API key columns that only the gateway opens, are left out because oh-fx has no Vercel AI Gateway or Grok transport yet. Choosing a provider switches the running session in upstream's order, with upstream's `Already using …`, settings-load, `Preparing …`, catalog, `Switched to … with …`, and unsaved-selection notices, and a connection is named by its id where upstream says `Configured provider`. The conversation, Fast mode, and the reasoning effort carry over, the token calibration and fixed request overhead measured against the previous provider are dropped, since two configured connections can serve the same model ID where upstream's providers never do, auto review moves to the new provider's reviewer, a subagent child started after the switch runs on the new provider while one started before it keeps its own, as upstream records a child's provider when it admits the child, the saved session records the new provider and model, and only `provider` and that provider's model are saved to the user settings, which drops `fast_mode_model_bound` as upstream's provider patch does. The model is `OH_FX_MODEL` or the target's saved model when the target lists it, and otherwise its first, from the Codex catalog for the Codex subscription and from a connection's `models`, read from the settings as they are when the switch starts. A model catalog requested before a switch is dropped and asked for again from the new provider. Choosing Codex without a saved login reports `Run oh-fx login codex, then try switching again.`, upstream's notice for a switch that cannot sign in; upstream starts the ChatGPT sign-in in the footer instead, which oh-fx does not port yet. The switch runs on the agent thread before the next command is read, so Ctrl+C cannot cancel it as it cancels upstream's background preparation.
- `/logout [vercel|codex|grok]` signs out as upstream's does, with upstream's notices: it removes the Codex login, or the Grok login and revokes its refresh token, and without an argument picks the selected Codex subscription, else the only saved subscription login. Signing out of the selected Codex leaves the session on Codex without a credential, dropping the model catalog, the capability lookups, the auto reviewer, and the subagent route that held the login, as upstream drops its selected credential and resets its model cache. A subagent child started earlier keeps its connection but no longer sends the removed login's token, as upstream's children lose the credential with it, and a session title request still running is stopped, where upstream lets a title request it already started finish with the copy of the token it took. It then reports `No connected provider is available. Use /provider to sign in.`, so a prompt sent next reports upstream's `Codex needs a subscription login. Run /login, open Connections, then choose Codex subscription.` and waits; upstream would first fall back to a Vercel AI Gateway credential or a saved Grok login, and oh-fx has no Gateway transport and does not activate Grok yet. oh-fx has no oh-fx login of its own, so `/logout vercel`, and `/logout` with no single saved subscription, report `No oh-fx login session found.`. While a turn or compaction runs, signing out of the selected provider reports upstream's busy notice, and signing out of another one runs beside the work, so a Grok revocation never holds up the turn. `OH_FX_AUTH_MODE=host-managed` makes `/login` and `/logout` report `Authentication is managed by the host.`, as upstream's host-managed mode does.
- A launch with Codex selected and no saved login opens the shell signed out instead of failing, and so does `/logout` of the selected Codex; the status line starts with upstream's `run /login`, and the provider column marks no provider `current`. A session resumed at launch or from the session picker without its Codex login reports upstream's missing-login notice as it opens, and a paused response it holds is not continued: upstream's `sign in to let the interrupted response continue automatically` warning shows and the checkpoint stays pending, as upstream leaves it when no credential is available. A prompt sent while signed out shows its card and upstream's `Codex needs a subscription login. Run /login, open Connections, then choose Codex subscription.`, and waits: typing goes on, Enter on other text keeps it in the composer, slash commands run, and Enter on an empty composer checks the login again, repeating the notice or, when a login was saved meanwhile, running the prompt on the session's model, or on the model a switch would pick when the catalog no longer lists it, after binding the saved session to the new login so its recovery checkpoints name that account. Ctrl+C drops the waiting prompt, as upstream drops it, and leaves the draft as it was, and `/clear`, `/new`, and `/reset` drop it with the conversation. `/compact` with context reports upstream's `Compaction was not started. Check authentication and try /compact again.`, or its busy feedback while a prompt waits. Upstream also opens its first-run setup hub on such a launch unless `FX_SKIP_ONBOARDING` is set; that hub offers the Vercel and Grok sign-ins oh-fx has no transport for, so oh-fx leaves it out and relies on the status-line hint and `/login`.
- `/settings` without an argument opens upstream's settings menu below the composer, during a turn too. It shows `Settings` with the number of matching rows and the `All`, `Interface`, `Agent`, `Notifications`, and `Advanced` tabs, falling back to the active tab alone on a narrow terminal, then one row per setting with its choices aligned after the widest label, the current choice and the selected label highlighted, and upstream's hint ladder, `↑↓ navigate     tab category     ←→ change     esc close`, in place of the status line, or `press ctrl+c again to exit` while Ctrl+C is armed. Up and down, or Ctrl+J and Ctrl+K, move through the rows and wrap, Tab and Shift+Tab switch the category, left and right move the selected setting to its previous or next choice, and Esc closes the menu and clears the composer. Enter, or right, on the `Model` row opens upstream's inline model list under the row, up to six models at a time, or `Loading models…`, `No models found`, or `Models unavailable` while there are none to show, with the `Model` row at the top of the menu, as upstream lays it out. When fewer than six model rows fit, the list scrolls by the rows it shows, so the highlighted model stays in view; upstream places the list as if six rows showed, which can hide the model that Enter would apply. Up and down move through the models, and Enter, or left, applies the highlighted one with the session's reasoning effort, when the model offers efforts, and Fast mode, when the model has a fast tier, closes the list, and leaves the settings menu and its search as they were, as upstream's model-only pick does; right there does nothing, and Enter on other rows does nothing. The list starts with an empty filter and keeps it when the catalog arrives, and text typed while it is open filters both the settings rows and the models, as upstream syncs both menus with the composer. Tab and Shift+Tab close the list as they switch the category, Ctrl+P closes it and clears the search, and Esc closes the settings menu first and leaves the model menu open on its own, as upstream's Escape order does. Super+R does nothing while the menu is open, as upstream's settings menu keeps the session picker away, and a key the menu handles disarms a pending Ctrl+C exit, as any other key does. Ctrl+P otherwise does nothing while the menu is open, and `/model ` typed into its search opens no model columns, as upstream's settings menu keeps the keyboard and the footer. What is typed stays in the composer and filters the rows by label, description, value, and setting name, as upstream's search does, and the empty search says `No settings found.`. Each change is applied as upstream applies it: the status line rows as `/statusline <item>`, `Fast mode` as `/fast`, `Permission mode` as `/permissions <mode>`, and `Startup scrollback` as `/settings startup-scrollback`, each with its notices, while `Session titles` and `Prompt history` switch at once and are saved to the user settings. Switching `Prompt history` off stops recording as soon as the key is pressed, before the controller answers or its save waits for the settings lock, as upstream disables history before saving; switching it on records again only once the save succeeds and every step pressed since has been answered. Left and right send a step that the controller applies to the setting's current value, in the order the keys reach it, as upstream applies each change to its current settings, so presses made before the controller answers each move the setting once more, and the rows follow every snapshot the controller sends after a change. oh-fx offers ten of upstream's rows: the three status line items, `Model`, `Reasoning effort`, `Fast mode`, `Permission mode`, `Session titles`, `Startup scrollback`, and `Prompt history`. `Model` shows the current model without choices. `Reasoning effort` offers `default` and the model's efforts, or shows `default` alone when the model offers none and none is set, and a step sets the session's effort and saves it silently, as upstream's settings pick does, or reports upstream's `<effort> is not available for <model>` when the model does not offer it. `Fast mode` offers its choices only when the model comes with a fast mode or it is on, as upstream does. Upstream's `Slash menu categories` and `Collapse tool calls` for the settings they switch, which oh-fx does not read yet, `Sound level` for notifications, which oh-fx does not have, and `Ultra mode` for the ultrafast mode it switches, so the `Notifications` tab shows no rows. When the settings cannot be loaded, `/settings` writes upstream's settings status notice instead, as upstream does; `model_config_source` names where the `gateway` model setting comes from, as upstream's does, though oh-fx has no gateway connection yet.
- `/statusline` toggles the context, session, and workspace segments of the status line as upstream does, saving each choice under `statusLine` in the user settings and moving workspace copies of the context and session choices into them behind a recovery snapshot. Without an argument it opens upstream's status line menu in the composer's place, hiding the composer and its cursor while it is open as upstream's compact menus do: `Status line` and a row for each segment with its `off` and `on` choices, the current one highlighted, and upstream's `↑↓ navigate     ←→ change     esc close` hint in place of the status line. Up and down, or Ctrl+J and Ctrl+K, move between the segments, Enter, left, and right toggle the selected one: the row and the status line change at once, and the controller flips the segment from its own value in the order keys and commands reach it, so no toggle is lost when several arrive in one burst of input or while a `/statusline <item>` sent before them is still running, and the row then follows the controller's value, as upstream's menu applies each change to its current settings. Each toggle is saved as `/statusline <item>` saves it but without its notices, unless saving fails. Esc closes the menu. As upstream does, other keys, Ctrl+C and Ctrl+D included, do nothing while it is open, and a paste still reaches the hidden composer. The command takes no argument completion. The context segment shows the input tokens of the latest model request, followed by the model's context window once the agent has looked up the model's capabilities, which it does before the second request of a session, or before the first when a reasoning effort or Fast mode is set, and again before the next request after `/model` picks another model; until then it shows the tokens alone, where upstream reads the window from its model cache at once. A resumed session shows the segment from its first request, since saved sessions do not keep token counts yet. The session segment shows the session's title after the model, cut to 32 cells as upstream cuts it. As upstream does, the model is followed by the reasoning effort when it is not auto and the model offers it, or when it is set and the model's capabilities are not known yet, and by the monochrome `⚡︎` marker in Fast mode or for a model whose ID ends in `-fast`; while the `/model` picker's effort or mode column is open, both show the model, effort, and mode it has selected, and a partial effort or mode query shows the filtered row that Enter or Tab will choose, where upstream looks that row's index up in the unfiltered options and can show another effort or Fast state. Upstream's vivid yellow Ultra marker is left out, since no oh-fx turn runs Ultra mode yet, and the `⚡︎` marker follows Fast mode itself, so a `fast_mode` saved without a model binding shows it, where upstream runs such a session at priority without the marker. The workspace segment shows the workspace path and its Git branch or detached commit, checking `HEAD` on each frame and reading it again only when it changes, as upstream does.
- `/fast` checks the model's fast tier through the connection's model capabilities, the Codex catalog for the Codex subscription, and switches Fast mode for the next turns of the session. A capability lookup that found the Codex catalog unavailable is not repeated by later turns, as upstream's turns read its model cache without reloading it; `/fast` and `/model` look the model up again, as upstream's model menus reload that cache, and the next turn uses what they found, while a catalog fetched once is kept for the session. During a turn or a compaction, a `/model`, `/fast`, or picked model that needs a catalog not fetched yet waits for it while the turn streams and stays cancellable, then applies, in the order it was sent, when the catalog arrives or, at the latest, before the next turn starts; upstream fetches it while it runs the command, before the shell reads the next key. As upstream does, `/fast` and `/model` save the provider, the model, and the Fast choice bound to that model to the user settings, moving workspace copies of the Fast choice into them behind a recovery snapshot, and `/model` turns Fast mode off when it picks another model. A model chosen in the `/model` picker, or typed as `/model <id> <effort> [normal|fast]`, also sets and saves its reasoning effort when the model offers efforts, moving workspace copies of `effort` behind their own snapshot, and keeps Fast mode only when the model has a fast tier and it was chosen, as upstream's picker does; the session saves the effort beside the model and the Fast choice. A Fast choice saved this way applies at launch, to the interactive session and to `ask`, only while the session's model is the one saved beside it: a launch whose `--model` or `OH_FX_MODEL`, or a workspace's saved model, selects another model starts without Fast mode unless `--fast` asks for it, as `/model` would leave it, and a `fast_mode` saved without that binding still applies to every model. Upstream keeps a saved Fast choice for a model chosen at launch and drops only its compiled-in default Fast mode, so another model with a fast tier runs at priority, under `FX_MODEL` without the `⚡︎` marker, which follows the binding; oh-fx follows the binding upstream writes beside every saved choice instead, so a launch flag and `/model` leave Fast mode alike. They also save the model and the Fast choice to the saved session, as upstream does. A choice the user settings cannot hold still applies to the session and is reported with upstream's notice. A successful save is silent, as one from `/permissions` is: upstream also reports a save that moved workspace values, naming the recovery snapshot, and names a workspace or environment setting that still overrides the saved value in fresh sessions, which needs the source of each setting that oh-fx's settings loader does not keep yet.
