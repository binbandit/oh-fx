# Modes

- Modes come from upstream's `core/modes` and `builtins/modes.zig`: the built-in `code` and `ask` modes, with `ask` as the default, each with its permission mode and tool policy. As upstream's `ask` does, `oh-fx ask` advertises the tools the default mode allows, and gives the model the guidance of a provider-run tool such as `web_search` only when the mode allows it, and refuses a call the mode blocks with upstream's `tool_execution_failed` result before the tool runs. The mode works from the tool specs the agent read when it was built. Both built-in modes allow every tool, so neither changes what `ask` advertises or runs. Like upstream's, the interactive session uses no mode. A subagent works under its parent's mode, as upstream's `runAskChild` projects the child's tools through it, so it is offered only the tools the mode allows and a blocked call is refused the same way. ACP session modes arrive with `ofx-acp`. Upstream's JS host restores a saved mode only in its browser build, which oh-fx does not ship.
