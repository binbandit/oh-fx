# Vercel AI Gateway

- The gateway route reads upstream's credential sources in upstream's order: `VERCEL_OIDC_TOKEN`, then `AI_GATEWAY_API_KEY`, each ignored when blank, then the Vercel sign-in that `oh-fx login` saves, then the stored key that `oh-fx setup` saves. A sign-in that cannot be loaded or refreshed is skipped, as upstream skips it, and `credential_source` in `settings.json` pins one source with no fallback, as upstream's does. `OH_FX_AUTH_MODE=host-managed` sends no credential. Messages and labels name `oh-fx login` where upstream's name `fx login`, such as the `oh-fx login` source in `status`, and `oh-fx logout` prints `Signed out of oh-fx.` where upstream prints `Signed out of fx.` The interactive shell stops at startup with the missing-credential message, where upstream opens signed out with `/login` and `/provider` guidance, because `/provider` cannot take a key and `/login` cannot sign in with Vercel yet.
- `oh-fx login` selects the gateway with the new sign-in as upstream's does, saving `"provider": "gateway"` and `"credential_source": "fx_login"`, once the sign-in has a usable team. It keeps the saved gateway model, or the default one, where upstream loads the gateway's model catalog with the sign-in, refuses a sign-in whose catalog is not authenticated, and saves a catalog model, because the gateway's model catalog has not been ported. For the same reason `oh-fx teams` saves the chosen team without first checking that it can list AI Gateway models, where upstream refuses a team whose catalog cannot be loaded with `oh-fx teams: selected team could not access AI Gateway`.
- `/logout vercel` in the interactive shell removes and revokes the sign-in and forgets the chosen source as upstream's does, but the running session keeps the credential it started with until oh-fx restarts, where upstream recalculates the active source at once; that recalculation comes with the shell's Vercel sign-in. A removal that could not be confirmed as durable still shows upstream's `Could not confirm durable oh-fx logout. The active source was recalculated.`
- The transport refreshes the sign-in's access token before a request once the token is due, as the Codex transport does, and keeps the current token when the refresh fails or names another team. Cancellation never loses rotated tokens. In the interactive session, a turn cancelled during the refresh stops waiting at once, and the refresh carries on by itself and saves the rotated tokens. When the session ends, oh-fx stops a refresh that has not sent its token request yet, since nothing has been consumed, and waits for one that has, at most 18 seconds from the session's end: the 15-second OAuth request limit and 3 seconds to save. A ChatGPT refresh is waited for at most 20 seconds from its start. Elsewhere, such as in `ask`, cancellation stops a refresh that is still waiting for the sign-in's lock or the issuer's metadata, but once the token request has been sent the turn waits for its answer, within the 15-second OAuth request limit, and saves it before the turn ends; the ChatGPT refresh gives a sent request only 2 seconds. Upstream's refresh runs on the agent worker and cannot be cancelled, so a cancelled turn ends only once the refresh returns. Upstream re-reads the saved sign-in before each step unless it was checked in the last 30 seconds, so it also picks up a token another process refreshed earlier. After an HTTP 401 to a request sent with the sign-in, oh-fx forces one refresh and resends the request once with the new token, as upstream does, and a second rejection or a failed refresh ends the turn with the authentication error. oh-fx replays only after an HTTP 401, where upstream also replays a stream that fails as unauthorized before any output or tool call. The repair hint after the error names `/login`, as upstream's does, although `/login` cannot sign in with Vercel yet.
- The stored key follows upstream's store:
  - On macOS it is read with `/usr/bin/security find-generic-password` and saved through `security add-generic-password -U -w`, whose own hidden prompt takes the key. The item's service is `OH_FX_AI_GATEWAY_API_KEY` where upstream's is `FX_AI_GATEWAY_API_KEY`. Its account is `USER`, then `LOGNAME`. Without either, oh-fx finds no stored key and saves none, where upstream asks the operating system for the account name, because oh-fx calls no C library functions. oh-fx also runs `security` only when `HOME` has a `Library/Keychains` folder. A process whose `HOME` is not a macOS user's home, such as a test, never reaches the Keychain.
  - Elsewhere the key lives in `$XDG_DATA_HOME/oh-fx/api-key` (default `~/.local/share/oh-fx/api-key`), where upstream keeps `~/.fx/api-key`. The file is `0600` in a `0700` folder, with line ends trimmed and an 8 KiB limit, as upstream's is.
  - `OH_FX_DISABLE_KEYCHAIN` set to `1` or `true` replaces upstream's `FX_DISABLE_KEYCHAIN` and turns the store off on every platform, as upstream's switch does.
- `oh-fx setup` keeps upstream's prompt, masking and messages. On a terminal without the Keychain it switches the terminal to raw input before it writes the prompt, where upstream writes the prompt first, so a key pasted right after the prompt appears is never discarded.
- A saved session whose provider is the gateway resumes on the gateway only when one of those sources is present. Otherwise it continues with the selected provider and its rebind notice, as a session saved with a provider oh-fx cannot use does.
- `OH_FX_E2E_GATEWAY_CHAT_URL` and `OH_FX_GATEWAY_CHAT_URL` replace upstream's `FX_E2E_GATEWAY_CHAT_URL` and `FX_GATEWAY_CHAT_URL`, and the first outranks the second, as upstream's does. Both take only a loopback `http://` URL with a port. An end-to-end URL that is not loopback is ignored, as oh-fx's other end-to-end overrides are, where upstream fails the request with `InvalidE2EGatewayUrl`.
- The route reads the gateway's catalog in its picker view, with the route's current credential and a due sign-in refreshed first, the first time a turn needs a model's reasoning efforts, Fast mode, context window or image input, or a picker opens, and keeps it for the session, as it keeps the Codex catalog; lookups that arrive while it loads wait for that one load. Upstream warms it at launch, refreshes it in the background, reloads it when the credential changes, and retries a failed load a second later. A model the catalog does not list gets no efforts, Fast mode or image input, as upstream's does. Requests still carry no `maxOutputTokens`, where upstream sends the catalog's output limit bounded as `request_output_tokens` bounds it, and when the catalog is unavailable oh-fx knows no context window, where upstream falls back to `vercel_model_policy`'s windows. The model menu's note for the Vercel sign-in names `oh-fx login` where upstream's names `fx login`.
- Upstream's `review_model` setting and `FX_REVIEW_MODEL` choose the reviewer model for every provider. oh-fx does not read either yet, so the gateway reviews with `openai/gpt-5.6-luna`.
- `oh-fx status` lists the Vercel AI Gateway among the connected providers when an environment source, a Vercel sign-in, or a stored key is present, and reads the stored key and the sign-in to find out, since oh-fx has no Keychain metadata check.
- Requests name oh-fx where upstream names fx: `User-Agent: oh-fx/<version>`, `X-Title: oh-fx`, and `HTTP-Referer: https://github.com/binbandit/oh-fx`, and a `zai/glm-5.2` request body carries `"headers":{"user-agent":"oh-fx/<version>"}`. Every other header and body byte matches upstream's agent request.
- Every tool description, including an MCP tool's, is cut to 1,024 bytes at a character boundary, as oh-fx's other transports cut them; upstream cuts only built-in descriptions, at a byte offset.
- The transport makes one attempt per request and leaves retries to the agent, as upstream's agent path does. Upstream's transport-owned callers, such as compaction summaries, also retry HTTP 429 and 5xx answers and dropped connections inside the transport, for up to three attempts; oh-fx's gateway transport does not.
- An error response's body is read up to 64 KiB and for at most 30 seconds, as for custom connections; upstream reads it whole. The response head is awaited without a limit, as upstream's agent path does, and the ten-minute stall watchdog runs once the head has arrived.
- A stream that ends before its `finish` event, at `[DONE]` or when the body ends, fails as `StreamInterrupted` and is retried as a network interruption, under `⚠ Network interrupted · StreamInterrupted`, where upstream labels the retry `Response ended early`; oh-fx's recovery has no response-interruption cause yet. A `length` finish fails as `OutputTruncated`, as on oh-fx's other transports.
- Tool calls follow upstream's reconciliation of streamed input, final calls and provider results, with these differences:
  - A tool call whose input is not valid JSON keeps the provider's text, which the agent diagnoses and saves as `{}`, where upstream replaces it in the transport. A final `input` that is a bare number, boolean or `null` reaches the agent as that value and is refused as non-object arguments, where upstream refuses it as malformed ones; a provider-executed call with such input fails as `MalformedProviderToolArguments`, as upstream's does.
  - Each streamed call announces its start once, when its input starts; upstream announces it again with a label taken from the first string in its arguments, which oh-fx's tool rows do not take.
  - A call the provider streams under one id and finalizes under another keeps its provisional row under the streamed id, since oh-fx's tool calls carry no provisional id; the replay and the next request use the final id, as upstream's do.
  - Calls with malformed or duplicate identities, provider results that name no single provider-executed call, and missing final results fail the request with upstream's error names (`MalformedProviderResultIdentity`, `MalformedAuthoritativeToolIdentity`), where upstream's agent rejects the completion; the turn fails as upstream's does.
  - A final call that reuses the streamed id another final call was reconciled from fails as a duplicate identity (`MalformedAuthoritativeToolIdentity`). Upstream admits it, folds its provider metadata into the other call's replay part, and replays it without its own.
  - Provider replay counts 96 bytes per part toward its 4 MiB limit, where upstream counts its own record size.
- The gateway's permission reviewer retries HTTP 408, 425, 429 and 5xx answers, in-stream provider errors and dropped requests once, and gives up on other statuses, content filters, refused or unreachable connections and stream errors, as upstream's does. A connection that times out while connecting is not retried, where upstream retries it once, since oh-fx's connection errors do not tell a connect timeout from a refused connection. The review's pending tool result is sent as a plain `text` result, as upstream's gateway review sends it; the other transports send the same text.
- A provider error reported in the stream is masked, with the key and anything that looks like a credential hidden, before it is cut to 600 bytes, and the cut ends at a character boundary; upstream cuts the raw detail at a byte offset. The resolved model a response names is masked the same way before it reaches the trace log.
- reqwest connects, sends the body and reads the response head in one call, so the `gateway` trace lines between `before_request_open` and `after_receive_head` are written together once the head arrives, and a failure there is written as `http_open_connect_error` when connecting failed and as `receive_head_error` otherwise, with oh-fx's error code in `err=`. reqwest pools connections itself, so `pool_borrow` and `pool_body_drain` are not written. The lines carry no turn or step ids yet, because a provider request does not carry the step's trace context.
- `oh-fx models` reads the catalog within 30 seconds and up to 8 MiB, as oh-fx reads the Codex catalog, where upstream waits for it without either limit, and it prints model ids through upstream's terminal-safe encoding, as the Codex listing does, where upstream prints them raw. `OH_FX_GATEWAY_BASE_URL` and `OH_FX_E2E_GATEWAY_MODELS_URL` replace upstream's `FX_GATEWAY_BASE_URL` and `FX_E2E_GATEWAY_MODELS_URL` and take only a loopback `http://` URL with a port. An end-to-end URL that is not loopback is ignored, as oh-fx's other end-to-end overrides are, where upstream fails the request with `InvalidE2EGatewayUrl`, and a base URL that is not loopback is ignored without upstream's `gateway` trace line. The Vercel sign-in's `teamId` query is added to an end-to-end URL too, where upstream's replacement drops it. A transport failure counts as retryable in the `model_catalog_load` line when it timed out or broke after the connection was made, and not when the connection failed, close to upstream's reset, closing and timed-out connections.
- The catalog's order leaves out the rank upstream gives one vendor's models by name, as oh-fx's source never names that vendor; its models sort with the providers upstream does not rank. Every other provider keeps upstream's rank, and upstream's tiers, tool-use preference, release order and id order are kept. The picker's highlights likewise leave out the two featured families upstream names for that vendor, its larger allowance and family limit in the provider pass, and the model line upstream keeps out of that pass, so its models fill the picker like any other provider's; every other highlight, allowance and exclusion is upstream's.
- An HTTP error's message, for a turn, a review or `oh-fx credits`, masks the configured key and anything that looks like a credential before it is cut to 1,024 bytes, or to 600 for the recovery diagnostic, so a key that crosses the cut never leaves a prefix; upstream cuts first.
- `oh-fx credits` reads the credits within 30 seconds and up to 1 MiB, where upstream waits for them without either limit, and prints the balance, usage and plan, and an error's text, through upstream's terminal-safe encoding, where upstream prints them raw. `OH_FX_E2E_GATEWAY_CREDITS_URL` replaces upstream's `FX_E2E_GATEWAY_CREDITS_URL` and takes only a loopback `http://` URL with a port; any other value is ignored, where upstream fails the request. The shell's `/credits` comes with a later slice.
