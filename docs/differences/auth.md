# Logins and credentials

- Grok sign-in observes cancellation while waiting for its publication lock and immediately before the synchronous durable write. Synchronous durable filesystem operations cannot be interrupted once started. Successful native Grok sign-in stores only the private session and preserves the active provider, every saved model, and the `settings.json` file bytes. Upstream activates the Grok subscription after sign-in, but its request route is available there. Activation, authenticated model listing, and the Grok refresh consumer are deferred until the next OH-9 PR supplies that request route; this staged login keeps the existing successful command output and leaves subsequent requests on their usable provider.
- The Grok login is stored in `$XDG_DATA_HOME/oh-fx/grok-auth.json`, with `grok-auth.lock` beside it, instead of upstream's `~/.fx` directory. Both subscription providers use a shared private session store, durable writes, and clock helpers. ChatGPT refresh uses the shared refresh parser and access representation; the Grok refresh consumer is deferred with its request route. Provider policies preserve their own filenames, error categories, and account validation rules.
- The ChatGPT and Grok sign-ins start the browser with `open` or `xdg-open` and go on to wait for the callback while the launcher runs; a thread reaps it. Upstream waits for the launcher to exit first. Both ignore whether it succeeded, so the sign-in prints the same URL and behaves the same either way.
- Grok authentication uses the fixed upstream endpoints. Tests supply explicit loopback HTTP endpoints to the constructor instead of upstream's `FX_E2E_*` environment overrides. Browser authorization retains upstream's protocol `referrer=fx` value. A loopback listener receives browser callbacks; Grok token exchange, user information, and revocation use the shared bounded HTTP client and its standard proxy settings. Origin headers and preflight requests are inspected only for Grok's configured origin; ChatGPT's callback returns after parsing the request line. Unrelated headers need not be UTF-8.
- A wrong-state callback GET without an Origin header aborts Grok sign-in, while ChatGPT ignores it, matching each provider's pinned upstream classifier. ChatGPT retains its session after a successful refresh HTTP response whose body is not JSON; a parsed response with an invalid token shape still retires the session. Grok refresh remains deferred with its request route.
- Native Grok login supplies its input descriptor to the authentication API. The manual-code reader polls that borrowed descriptor every 50 milliseconds so cancellation does not leave a blocked input worker. Tests use owned input through the same consumer instead of inheriting process input, including Git's pre-push ref-update stream.
- The ChatGPT login is stored in `$XDG_DATA_HOME/oh-fx/chatgpt-auth.json` instead of `~/.fx/chatgpt-auth.json`, in upstream's file format and with upstream's lock file. The sign-in, token, and Codex endpoints are fixed; tests pass their own endpoints to constructors, and upstream's `FX_E2E_*` endpoint variables do not exist, so no oh-fx variable can point these requests at another host. Standard proxy settings such as `HTTPS_PROXY` and `ALL_PROXY` still route them through the configured proxy.
- The sign-in callback compares `state` in constant time and serves browser connections concurrently, each with its own 30-second socket timeout, so an idle preconnect or a slow request cannot hold back the real callback; upstream serves them one at a time. Its pages and messages say oh-fx, and requests carry an `oh-fx/<version>` user agent.
- The ChatGPT sign-in redirects the browser to `http://127.0.0.1:<port>/auth/callback`, the address its callback listener binds and the one OpenAI's Codex CLI uses, where upstream uses `localhost`, which some browsers resolve to `::1` first. The code exchange sends the same redirect URI. A token response without `expires_in` takes the session's expiry from the access token's `exp` claim, as refreshes already do, where upstream fails the sign-in; an `expires_in` that is present but not a positive integer still fails it.
- oh-fx names itself to OpenAI with `originator=oh-fx` when signing in with ChatGPT and in the `originator` header of every Codex request, matching its `oh-fx/<version>` user agent, where upstream sends `fx` in both.
- A SIGINT or SIGTERM while `ask` loads or refreshes the ChatGPT login, during preparation or before a Codex request, stops the wait for the credential lock, and no refresh starts once the signal has been noticed. A refresh already sent gets up to 2 seconds to answer, so rotated tokens can still be saved, and `ask` then exits by the first signal it received, even if preparation failed at the same moment. Upstream lets the refresh run to its 15-second timeout and then re-delivers the first signal. A refresh still unanswered after 2 seconds is abandoned, so if the server rotated the refresh token anyway, the next run asks for a new sign-in.
- In the interactive session, a ChatGPT login refresh runs on its own: a turn cancelled while it waits stops waiting, and the refresh still saves the rotated tokens when the token endpoint answers. When the session ends, oh-fx restores the terminal first, starts no further refresh, and gives the agent 2 seconds to stop. A refresh still in flight then is waited for until it saves or fails. Each refresh is bounded by the 2-second credential lock wait, the 15-second OAuth request timeout, and its save, so the wait for one is capped at 20 seconds from when it started, those bounds plus 3 seconds for the save, in case the agent thread can no longer run it. Upstream joins its agent worker without a time limit after restoring the terminal and relies on its refresh's own bounds.
