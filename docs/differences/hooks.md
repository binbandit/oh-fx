# Hooks and Herdr reporting

- The lifecycle hooks of `core/hooks` are first-party handlers compiled into oh-fx, as upstream's are; neither reads hooks from settings nor runs a configured command. Freezing the hook runtime consumes it, so a handler cannot be registered after the freeze or the view read before it, where upstream returns `RuntimeFrozen` and `RuntimeNotFrozen`; a runtime frozen with no handler holds nothing, so dispatching it is one branch. A `PostTurnEnd` or `AttentionRequired` handler returns nothing and the runtime writes no handler start or finish lines, because oh-fx has no debug trace; upstream records a side-effect handler's error only in that trace and runs the next handler either way. An invocation carries its scope kind and turn but not upstream's workspace root, session id or subagent id, and a `PostTurnEnd` input carries the turn's outcome but not the provider's completion disposition; no handler reads them. The agent dispatches `PostTurnEnd` after it reports the finished turn, with paused recoveries reported as paused, and runs the handlers on tokio's blocking thread pool, waiting for them before it returns the turn, where upstream runs them on its agent worker thread: the session's runtime has one thread, so a handler that blocks, as a Herdr report can for 250 ms, never holds it. The interactive session shows the finished turn once its handlers return, where upstream queues the turn's presentation before it runs them. Child agents dispatch no lifecycle hooks, where upstream's children dispatch them with the subagent scope, because no first-party handler acts on that scope. The interactive shell dispatches `AttentionRequired` when its permission or question prompt becomes active, and a request that replaces a prompt that is still open dispatches nothing, as upstream's prompt activation does.
- Foreground Herdr reporting uses `OH_FX_HERDR` for the application opt-out while retaining the third-party `HERDR_SOCKET_PATH` and `HERDR_PANE_ID` variables and the upstream `custom:fx` source and `fx` names. Working is reported when the session starts a prompt's turn, before the provider starts; upstream reports it when the prompt enters the worker's queue, so a prompt queued behind a running turn reports working when its own turn starts instead of before the earlier turn's idle report. Startup reports the actual opened session, then idle and both names; a visible permission or question prompt reports blocked through upstream's `fx.herdr.attention_required` lifecycle hook, every interactive turn reports idle when it ends through the `fx.herdr.turn_end` `PostTurnEnd` hook, the startup, working and idle reports run on tokio's blocking thread pool, and terminal shutdown releases authority before a handled termination signal is re-raised. The release is serialized with reports and permanently closes the reporter; the last shared reporter drop provides idempotent fallback cleanup. Later session selection, manual compaction and route-recovery decision prompts still need lifecycle reporting, and sounds remain unimplemented. Socket failures are ignored and the 250 ms timeout applies only to receiving a response, as upstream specifies.
