# Compaction

- `/compact` runs manual compaction as upstream does and shows its activity line, `• Preparing compaction`, `• Compacting` once the summary is being written, and `• Stopping compaction` after Esc twice or Ctrl+C, followed by upstream's feedback, which a submission or Esc dismisses and which leaves after 1.5 seconds when there was nothing to compact or work was running. Prompts submitted meanwhile, from the moment `/compact` is submitted, wait in the held banner, and `/model`, `/fast`, `/clear`, `/new`, and `/reset` apply once it ends, as during a turn. As upstream does, the checkpoint is saved to the session before it replaces the conversation, so `-c` continues from it, and one that cannot be saved leaves the conversation whole and reports `Compaction failed. Try /compact again.`, where upstream says `Compaction could not confirm saved context. Reopen the session before retrying.` when the save was left uncertain. Automatic and provider-overflow compaction show no activity line yet; upstream shows the same line during the turn.
- An automatic compaction, before a request that would pass the compaction point or after the provider rejects one for exceeding the context window, shows upstream's activity line in place of the turn's from the moment the turns to compact are chosen: `• Preparing compaction`, then `• Compacting`, counted on the turn's clock, as upstream counts automatic and overflow compaction. The line leaves once the checkpoint is saved. A failure shows upstream's feedback, such as `Compaction failed. Try /compact again.`, which stays after the turn ends until the next prompt or Esc, and a turn that ends while its compaction still runs settles it as cancelled or failed, as upstream's worker does. Cancelling the turn during its compaction shows `Compaction cancelled. Try /compact again when ready.` at once, since oh-fx ends a cancelled turn at once; upstream shows `• Stopping compaction` until the turn's work stops. Upstream also distinguishes a checkpoint whose save could not be confirmed (`Compaction could not confirm saved context. Reopen the session before retrying.`); oh-fx reports a failed save as a failed compaction.
- Compaction runs as upstream's does without a session store, as under `--no-save`, even when `ask` saves its session, until `read_tool_result` lands. Compacted turns, tool calls, and earlier compactions are not saved as `M<n>`, `T<n>`, and `L<n>` records, and `read_tool_result` has no `search`, so the notes request tells the model that tool calls will not be available later, and a later compaction carries the earlier checkpoint's turns and entries forward instead of folding them into an `Earlier:` summary. A saved session stores the checkpoint in upstream's `fx-compactor-v1` encoding with `saved` false, an empty `earlier`, and no ledgers, and a resumed session renders exactly the text the model saw. A saved checkpoint that holds what oh-fx does not keep, an `earlier` summary, ledgers, `saved` true, or a turn with other than one user message, is read as its raw text, as upstream reads a damaged one, and a checkpoint without the marker, such as an older fx `<context_handoff>`, is continued as plain text without reading its state file. The usage of summary requests, which upstream adds to the session's usage, is not recorded.
- Before each model request, oh-fx measures the body its transport would send and calibrates the estimate with the input tokens the provider reported for the last request to the same model, as upstream does. It measures only while the model's context window is known or a provider overflow is being recovered, and once per step, where upstream measures every attempt, so there a retry of a request that a compaction has just shortened can compact again before it is resent. Requests carry no images yet, so the measurement has no image accounting. The transport sends the body it measured, as upstream does, and a retry builds it again.
- The compaction notes request tells the model that it comes from oh-fx, not from the user, where upstream names fx, as the system prompt introduces the assistant as oh-fx. Text oh-fx adds to a turn, such as the `Summarize what you just did.` prompt after silent tool steps, reaches the notes request as `[From oh-fx, not the user]`, the form upstream gives the text fx adds. Upstream leaves that prompt out of a turn's execution, so its compactor never sees it; oh-fx drops it from the conversation when the turn ends, as upstream does, so only a compaction during that turn can see it.
- A provider overflow is also recovered when it arrives as a provider error whose code or detail names `context_length_exceeded`, such as a Codex `response.failed` event, with the same single compaction and retry. Upstream recovers only a rejected request (`request_too_large`, or `invalid_request` with an overflow detail), so a Codex stream that fails this way ends its turn there.
- When a compaction covers every finished step of the running turn, the messages after the last step, such as the `Summarize what you just did.` prompt, stay after the checkpoint. Upstream drops them with the steps, so the rebuilt request ends with the turn's first user message and the model is not asked for its summary again.
- A summary request that fails or comes back empty is not sent again to another model family. Upstream retries it once on `openai/gpt-6-sol` or `anthropic/claude-sonnet-5`, but only on the Vercel AI Gateway, where one credential reaches both, so the fallback arrives with oh-fx's gateway transport. Compaction also skips upstream's check that the conversation's credential belongs to its provider (`ContextCompactionUnavailable`): the summary request goes through the turn's own provider connection and credential.
- A summary request is retried as the turn loop retries a model request that has streamed nothing, at most 10 attempts on the same backoff, and shows no retry notice. Upstream leaves those retries to its provider transport; oh-fx's transports do not retry, so the agent does.
- Compaction writes no trace lines and keeps no trace ring for `/trace`, since oh-fx has no trace log yet.
- Compaction reads tool call arguments with serde_json, where upstream uses `std.json`. Arguments that repeat a key are read with the key's last value, where upstream treats them as plain text, and arguments with a number beyond a 64-bit float's range are treated as plain text, where upstream reads them. This changes only the one-line index of a call's argument values in the notes request and the skills and MCP features the checkpoint lists as used.
