# `read_file`, `write_file`, and `edit_file`

- `write_file` and `edit_file` open the target's anchor directory and every parent without following a symlink in any component, as `read_file` does, before checking the identities recorded at admission. Upstream opens the anchor by its absolute path, following symlinks above it. On macOS each of those directories must also be readable. A new file is put in place only if nothing has appeared at its path: through an exclusive rename, or, where the filesystem has none, a hard link that fails when the path exists, and the write fails where neither is available. A file that appears in that moment fails the write with the stale-preview message, where upstream replaces it. If the staged file's name cannot be removed after such a link, the success result names it. Before `write_file` reports `No changes to …`, it checks again that the parent directories, the file, and its content are the ones it read when the call was prepared. It fails with the stale-preview or changed-traversal message if any of them changed, and with `file mutation failed before commit` if the file can no longer be read. Upstream reports the content it read earlier. The diff preview upstream builds for its approval prompt is not built yet, so the interactive approval prompt names the target and what the change does to it instead.
- `read_file` opens the resolved path without following a symlink in any component, not only the last one as upstream does. It walks from `/` with `O_NOFOLLOW | O_DIRECTORY` descriptors, opened with `O_PATH` on Linux so directories that grant only search permission still work; on macOS each directory on the path must also be readable. A parent directory swapped for a symlink after the path was resolved fails as `NotRegularFile` instead of exposing the symlink target's content.
- `read_file` clips a line longer than its 2,000-byte cap after the last whole character that fits. Upstream cuts at the byte cap, which can split a multibyte character and replace the whole result with the binary-output notice.
- A file tool `path` that contains a NUL byte fails with `Cannot resolve path "a.txt\u0000x": InvalidPath`, which shows each NUL as `\u0000`, and a glob pattern whose static base contains one fails with `Unable to resolve glob search root: <path> (InvalidPath)`. Upstream cuts both at the NUL, so `a.txt\u0000x` reads `a.txt` there.
