# Auto-mode review

- Auto mode sends a file change to review when its target path contains a `.git` component or `.ssh/authorized_keys`, `.ssh/config`, `.ssh/rc`, `Library/LaunchAgents`, `Library/LaunchDaemons`, `.config/autostart`, `.config/environment.d`, `.config/systemd/user`, `.local/share/systemd/user`, `.config/fish/config.fish`, `.config/fish/conf.d`, `.config/git/config`, `.gitconfig`, a zsh startup file (`.zshrc`, `.zshenv`, `.zprofile`, `.zlogin`, `.zlogout`), a bash startup file (`.bashrc`, `.bash_profile`, `.bash_login`, `.bash_logout`, `.bash_aliases`), `.profile`, or `.pam_environment`. Names are compared after Unicode case mapping, with zero-width and bidi format characters removed, so a spelling that a case-insensitive filesystem opens as a protected name, such as `.GIT`, `.ssh` written with U+017F LATIN SMALL LETTER LONG S, or `authorized_keys` written with U+212A KELVIN SIGN, is also reviewed. Upstream matches a shorter list byte for byte, with `.git/hooks`, `.git/config`, and `.git/config.worktree` in place of any `.git` component, so a new `.GIT/hooks/pre-commit` on a case-insensitive filesystem, a submodule's `.git/modules/<name>/hooks`, or a new `~/.zshenv` skips review there.
- In auto mode, `shell` runs a command without approval when each of its `&&` stages is one of upstream's known reversible commands, such as `git status`, `git fetch`, `which`, `npm install`, `npm run <script>`, and `zig build`, and observes a session with `interact` without approval, as upstream does. oh-fx admits fewer commands: `git fetch` only with flags that cannot run a program or rewrite local refs and with no `+` refspec or `::` transport, `npm`, `pnpm`, `yarn`, `bun`, and `zig build` only with flags known to be inert before `--`, and no word that contains `^`, `#`, or `!` or starts with `=`, which a user's zsh options can expand into file names. Upstream also admits flags such as `git fetch --upload-pack=<program>` and `npm install --script-shell=<program>`. Only an unquoted, unescaped `&&` separates stages, so a quoted or escaped `&&` stays an argument of the command around it and that command's flags are still checked; upstream splits on it too. A reversible command whose `cwd` resolves outside the workspace needs review here, in keeping with the approval external reads need; upstream runs it. A `cwd` outside the workspace that does not exist goes through the same admission, so its absence is reported only once the call is allowed, and a command admitted only for the workspace resolves its `cwd` again when it runs and fails with `PathOutsideWorkspace` if the directory has left the workspace since admission. Every other shell call, including `stop`, goes to the auto-mode reviewer, as upstream hands it to its reviewer. Upstream first runs a read-only command requested with `profile: clean` directly, without a shell and without a review; that direct route is not ported yet, so oh-fx reviews such a command too, which costs a reviewer request upstream skips. As upstream does, every shell call needs approval in ask mode, which the interactive session asks for and `ask` asks for with its permission prompt when it can prompt; otherwise `ask` fails with `NonInteractivePermissionRequired`.
- In auto mode, a call held for review goes to the provider's reviewer model, as upstream sends it: a Codex login reviews with `gpt-5.6-luna`, and a custom connection with its `reviewer_model`, or with the session's model when the connection names none, capped at 2048 output tokens or the model's smaller `max_output_tokens`. The review sends upstream's policy prompt, its bounded evidence, and the one pending call, never the system prompt, project instructions, assistant prose, or other calls of the batch, and it accepts only a `permission_decision` call: streamed text never counts as a verdict. Like upstream's, a Codex review request carries no `session-id` or `x-client-request-id` header, even when the session is saved. Each attempt has upstream's 30 second budget, a malformed answer is retried once within the same budget, and a timed out review, or a Codex review that fails in a way upstream retries, is retried once with a fresh budget, as upstream. A clear verdict runs the call with the access an approval would grant. A caution holds it, and the model receives upstream's `tool_review_held` result with the reviewer's advice. When the review reaches no decision, because no reviewer is configured, the reviewer fails, times out, or answers without a valid decision, the turn's reviewer budget is spent, or the reviewer cannot see the complete action, `ask` holds the call with upstream's `tool_review_held` result and its `review_cause`, as upstream does in every session. The interactive session asks for approval with the approval panel instead: upstream holds the call there too, but an action held in auto mode can never be approved, so an unavailable reviewer would stop every command that is not known to be reversible. A caution is never turned into a prompt. A review that is under way when the permission mode changes keeps its verdict, as upstream reads the mode once for each call: a caution still holds the call after a switch to full access, and a clear still runs it after a switch to ask.
- A `shell` call that goes to the auto-mode reviewer is reported as started before the review begins, as upstream starts a call's visible lifecycle before it asks for permission, so `ask` prints its progress line and the interactive session shows the running phase while the reviewer answers. The call then runs, or finishes as a failure with its hold or denial; one whose review is cancelled finishes without a result. A file change under review is reported only once the review has decided, as upstream defers a file change's lifecycle until permission. Upstream's interactive session also defers a reviewed `shell.run` and shows the call meanwhile through the provisional row its stream created; oh-fx has no provisional rows yet, so it reports the call as started before the review there too.
- A turn remembers the actions a review held with a caution or with incomplete evidence and holds an identical call again without a new review, and it spends at most one reviewer attempt on an identical action whose review reached no decision, as upstream. It checks that memory after the deterministic admission, so an approval the user gave in the meantime still applies, where upstream returns the remembered hold first. Review holds are left out of later reviews' prior tool-result evidence by their call id and exact content, where upstream marks the results it holds; another tool's result is left out only if it repeats a hold byte for byte under the same call id, so it removes nothing upstream's reviewer would weigh. A held result is saved with upstream's `review_feedback` mark, in the session log and in a recovery checkpoint, and a turn continued from a checkpoint leaves out the results it marks, as upstream's does. A review's token usage is added to the turn's usage, where upstream adds it to the session's usage ledger.
- `shell` input sent with `interact` is reviewed without the receiver evidence upstream gathers from the running session, its launch command, working directory, and screen, which oh-fx's sessions do not expose yet, so the reviewer reports the evidence as incomplete and the call is held in `ask` or asked about in the interactive session.
