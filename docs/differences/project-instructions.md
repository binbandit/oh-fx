# Project instructions

- Project instructions read the global `AGENTS.md` from the configuration directory, `$XDG_CONFIG_HOME/oh-fx/AGENTS.md` (default `~/.config/oh-fx/AGENTS.md`), where upstream reads `~/.fx/AGENTS.md`. The directory is canonicalized first, so `<global-rules from="...">` names the resolved path. As upstream's context selection does, the global file is read only when `HOME` is set and resolves, a relative `HOME` resolves against the working directory, and ancestor `AGENTS.md` files are read only between `HOME` and the workspace. The default configuration directory below a relative `HOME` resolves against the working directory too. Upstream's `ask` stops on an assertion while it looks for its MCP profile below a relative `HOME`, before it gathers project instructions.
- Project instruction files open with `read_file`'s opener: no directory on the path may be a symlink, and the final `AGENTS.md` may be one only when its target lies inside the same directory, as upstream requires; that target is opened again without following symlinks and with `O_NONBLOCK`. Upstream follows symlinked directories on the path and opens a contained target without `O_NONBLOCK`, so a FIFO behind such a link blocks it, where oh-fx reports a symlinked rule file. Rule paths come from canonical directories, so the difference shows only when a directory is replaced by a symlink while the run reads it, which oh-fx reports as a missing or symlinked rule file instead of reading through the link.
- Project instruction paths that are not valid UTF-8 appear in `from`, `scope`, and `source_file` attributes and in notices with U+FFFD replacement characters, where upstream writes the raw bytes. Source digests hash the raw bytes, as upstream.
- Additional directories contribute no project instructions, as upstream's do not. A resumed session does not yet gather the instructions for the paths its earlier tool calls touched, which upstream adds to the first request after `--resume`.
- The interactive session shows project instruction notices, such as a truncated or omitted rule file with its override or repair hint, as `context` warnings in the transcript, each once per conversation: those for the instructions read at startup when the session starts and again after `/clear`, and those for scoped rules when a tool call adds them. Upstream reads the instruction files again for every prompt, shows each new notice when the prompt is submitted, and keeps context notices out of the compact transcript, showing them only in its full transcript (Ctrl+O), which oh-fx has not ported yet.
