# Skills

- Skill discovery checks a candidate whose directory listing reports no type with `fstatat` too, and scans it when it is a directory. Upstream skips such candidates, so on filesystems without `d_type` it finds no skills.
- The skill discovery warning ends after its diagnostics and omitted count. Upstream adds `relaunch with FX_TRACE=1 to write a trace log`, or the active trace log path, and writes each diagnostic to that log; oh-fx has no trace log yet, so the hint and the trace lines wait for one.
- A skill load keeps the `SKILL.md` descriptor whose metadata it checked and fails as `SkillResourceChanged` when that file's size, modification time, status-change time, device, or inode differ from what the check saw, as a write or a permission change normally makes them, or when `SKILL.md` no longer names the selected skill in its frontmatter. A `SKILL.md` read checks the name in the bytes it read, or, when `skill_file_bytes` cuts them short of the frontmatter, in at most 64 KiB + 1 bytes read again from that descriptor, and a read of another resource checks it the second way once the resource is read. A resource also fails as `SkillResourceChanged` when those fields change between opening and reading it. Upstream compares only size and modification time, and only across a single read, and does not check the name of a chunked `SKILL.md` read, so a `SKILL.md` rewritten in place between the check and the read is delivered under the selected name even when it names another skill.
- A skill resource that is a FIFO, device, or socket fails as `InvalidSkillResource` without being opened, and a regular resource is opened with `O_NONBLOCK` and read only when the opened file is regular. Upstream opens the resource, so it blocks on a FIFO until something writes to it, and a socket fails there as `NoDevice` because opening one gives `ENXIO`.
- Every entry in the explicit skill section, an ambiguous name's failure included, counts against the section's safety ceiling together with its trailing newline, and an entry that would pass it fails the section as `SkillContextTooLarge`. Upstream checks only the entries of skills it tries to load and appends ambiguity failures unchecked.
- An ambiguity failure in the explicit skill section lists every skill whose name matches the request ASCII case-insensitively, the set the explicit matcher counted when it reported the name as ambiguous. When those names differ, it gives each choice as a name and location, such as `"Review" at "/workspace/review", "review" at "/global/review"`, so every choice is one the skill tool resolves. Upstream lists only the locations of exact-name matches, so `$review` with skills named `Review` and `review` offers one location. When every candidate has the requested name, as in every skill tool ambiguity, the failure keeps upstream's text, and the skill tool still resolves names exactly.
- The `skill` tool's result budget is the default 64 KiB rather than a configured `max_tool_result_bytes`. A complete load always fits that budget, so it reaches the model whole without upstream's complete-skill marking, which only exempts it from the result store's truncation. A cancelled load returns the failure `skill failed: Cancelled`, where upstream propagates the cancellation. Both check cancellation when the call starts, and oh-fx checks it during the read of every load, where upstream checks it during the read only for complete loads.
- Skills are discovered from the canonical `HOME` for the catalog and for the `skill` tool's own discovery of a location the catalog did not advertise, and without `HOME` nothing is discovered. Upstream's catalog does the same, but its tool reads `HOME` as set, so with a symlinked `HOME` its workspace walk runs past the home directory, and without `HOME` it still scans the workspace roots.
- Workspace skill roots are scanned in the workspace and in each ancestor below `HOME`, as upstream does, but a workspace outside `HOME` scans only its own roots. Upstream walks the ancestors of such a workspace up to `/`, so a session in `/tmp/project` lists and loads skills that any local user can plant in `/tmp/skills` or `/.agents/skills`, with `/tmp` or `/` as the directory their symlinks may resolve into. Project instructions stop at `HOME` the same way in both.
- The interactive session discovers skills again on the agent thread before each prompt runs, scanning every root. Upstream refreshes the catalog on a background thread when a prompt is submitted, holds the submission until the refresh finishes, and skips the rescan when a fingerprint of the roots' entries shows nothing changed, so both run each prompt with the current catalog. A rescan of the 20 roots of a workspace two levels below `HOME` takes about 15 µs without skills and under 2 ms with 100 skills, and upstream's fingerprint also lists every root and stats every candidate, so it would save only the reads of unchanged `SKILL.md` files.
