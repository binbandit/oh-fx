# Slash commands

- Until menus and the remaining slash commands land, the interactive session offers `/help`, `/clear`, `/new`, `/reset`, `/resume`, `/rename`, `/login`, `/logout`, `/provider` (`/setup`), `/stats`, `/usage` (`/cost`), `/status`, `/model`, `/permissions`, `/allowlist`, `/undo`, `/mcp`, `/skills`, `/copy`, `/compact`, `/settings`, `/alias`, `/fast`, `/statusline`, `/workspace`, `/version`, and `/quit` (`/exit`), in upstream's order and with upstream's categories. Other slash commands report `Unknown command. Try /help.`
- `/status` shows upstream's interactive status body without `update_channel`, `build_channel`, and `build_revision`, since oh-fx has one release stream and embeds no build revision, and without `auth_expired`, since the Codex login's expiry stays inside the Codex transport, which refreshes a due token before each request. It also leaves out `auth_help`, which upstream shows only while no credential is active, since the interactive session does not start without one, and `team`, which names a Vercel AI Gateway team, since oh-fx has no gateway connection yet. `permission_mode` follows a switch made with Shift+Tab or `/permissions`. `connected_providers` names only the selected connection, or `Codex` for the Codex subscription, and follows a switch made with `/provider`; upstream also lists other providers with a saved credential, which oh-fx checks only when one is chosen. The workspace path is shown with U+FFFD replacement characters where it is not valid UTF-8. During a turn, `history_turns` counts the turns finished before it, as upstream's session history does.
- `/copy` puts the last completed assistant reply on the system clipboard through upstream's command, `pbcopy` on macOS and `xclip -selection clipboard` on Linux. A reply cut short by a cancellation is not copied, and a compaction that replaces the reply's turn forgets it, as upstream's session history does. Nor is anything from a failed turn: upstream keeps some failed turns in its history with a reply it copies, the notice of a turn stopped at the step limit or the partial reply a provider failure cut short, where oh-fx copies the last reply a turn completed. The command runs on the agent's thread, so a copy requested during a turn holds that turn's stream until it ends, where upstream holds its UI thread; a command still running after 5 seconds is killed and reported as a failed copy, where upstream waits for it.
- `/usage` and `/cost` answer as upstream does in a host without durable profile usage: `Durable profile usage is unavailable in this host; active session usage remains in memory.` oh-fx keeps no usage ledger yet, neither the per-session `usage-v2.json` sidecars nor the profile usage store that upstream's usage dashboard reads, so the dashboard, its session, 24-hour, 7-day, and 30-day scopes, and its token, model, and spend tables arrive with that ledger.
- `/workspace` answers every form with upstream's error for a runtime without workspace access, `Workspace access is unavailable in this runtime.`, since oh-fx has no additional workspace directories yet: the tools, the permission gate, and project instructions know only the launch workspace, and `--add-dir` and the saved `additional_directories` setting are not available yet.
- `/undo` reverses the session's latest committed `write_file` or `edit_file` change as upstream does, restoring the content the change replaced or deleting the file it created, and `/clear`, `/new`, `/reset`, and a session resumed from the picker forget the changes it could reverse, as upstream. Each change keeps the identities of the anchor directory and of every parent directory the commit passed through, and `/undo` reopens them without following symbolic links, refusing with `Could not undo <path>` when any of them is missing or is no longer the directory the change was committed in, then restores or deletes relative to the verified parent. Upstream restores and deletes by path name, so a parent directory renamed and replaced by a symbolic link after the change sends the restore or the deletion to the link's target. A FIFO, socket, device, or directory found at the changed path is left intact and reported with the same notice, where upstream renames the restored file over a FIFO, socket, or device and deletes one left where the change created a file; a symbolic link there is replaced by the restored file or removed, without touching its target, as upstream does. A restored file takes the exact permission bits of the file it replaces, where upstream creates it with them under the process umask, so a `0777` file comes back as `0755` under umask `022`; a file restored where none remains is created under the umask, as upstream does. The restored content is staged under a `.fx-stage-` name of fixed length beside the file, as `write_file` and `edit_file` stage theirs, where upstream appends `.tmp.<nanoseconds>` to the file name and so cannot restore a file whose name is within 24 bytes of the file system's name limit. Upstream also records each change's kind and commit time and writes a trace line when an undo cannot act; both serve only its trace log, which oh-fx does not have yet, so neither is kept.
