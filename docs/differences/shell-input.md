# Terminal input

- Keys typed while the interactive session starts reach the composer. Upstream's startup background and cursor position probes discard them.
- A bracketed paste settles only once the theme monitor has classified every byte that followed its end marker. When a read ends partway through what could be a terminal reply, such as `ESC [`, settlement waits for the next read or for the monitor's 75 ms idle timeout: a completed reply is filtered out and the paste is accepted, and anything else is a trailing suffix that rejects the paste, as a suffix that reaches the paste directly does. Upstream settles at the end of the read, so the rest of a split key sequence, such as `13u` or `A`, is then handled as Enter or Up.
- The input decoder consumes a whole OSC (`ESC ]`), DCS (`ESC P`), SOS (`ESC X`), PM (`ESC ^`), or APC (`ESC _`) string up to BEL or `ESC \`, however long the gaps between its bytes, so no part of a terminal reply, such as a background colour reply split by a slow link, is read as keys. `ESC` followed by anything but `\` ends the string and starts a new sequence, any other control byte ends it and is then read as a key, and a string longer than 4 KiB is dropped. A control sequence (`ESC [`) still waiting for its final byte when the 30 ms escape timeout passes is not dropped either: its remaining parameter and intermediate bytes and its final byte are consumed whenever they arrive, up to 256 bytes, and a control byte ends it and is then read as a key. Upstream drops such a sequence at the timeout and reads the rest of a split status or device attributes reply, such as `1n` or `2;22c`, as keys. A standalone 8-bit introducer, sent by a terminal in 8-bit control mode (S8C1T), starts the same sequence: 0x9b a control sequence, and 0x9d, 0x90, 0x98, 0x9e, or 0x9f a string, which a standalone 0x9c also ends; a byte with one of those values inside a UTF-8 character stays part of that character. Upstream drops such a byte as invalid UTF-8 and reads the rest of the reply as keys. The theme monitor still recognises only 7-bit replies, so an 8-bit background reply is consumed without changing the theme. When the theme monitor times out on a partial reply, it hands the bytes to the decoder instead of dropping them, so the rest of the reply is still consumed. While a theme query is outstanding, the theme monitor holds or has handed on a partial reply, a cursor position reply pair for the native-clear probe may still arrive, or the decoder holds any partial escape sequence, the approval prompt ignores 1, 2, 3, and Enter, and such a key restarts the 500 ms wait for a yes. Upstream decodes these string introducers as an ignored Alt key and the rest of the string as keys, drops a partial background reply after its idle timeout and reads the rest as keys, and has no such hold, so a split reply can pick an approval choice. Alt+], Alt+Shift+P, Alt+Shift+X, Alt+^, and Alt+_, which terminals also send as these introducers, now hide the keys typed after them until a control key, and Alt+[ hides the keys after it up to the next letter.
- Terminal input zeroes each byte in its read queues and in the theme monitor's reply buffers as it consumes it, and wipes both when it is dropped, so no copy of an authorization code paste stays behind in them. Upstream reads into a reused stack buffer, leaves its reply buffers as they are, and zeroes only the paste capture.
