# Usage

- The profile usage ledger is `$XDG_DATA_HOME/oh-fx/usage.jsonl`, locked through `usage.lock` beside it, where upstream keeps `~/.fx/usage.jsonl` and `~/.fx/usage.lock`. Its records are upstream's byte for byte, so a ledger fx wrote reads the same in oh-fx. `oh-fx usage` reads only oh-fx's ledger and never fx's, as upstream reads only its own profile.
- A session's `usage-v2.json` counts each provider request as upstream counts it: the request is saved when it starts and when it settles, with its API and wall time, and committed edits add their lines. A subagent's requests count in its parent session's usage, as upstream's do. Only agent model requests are counted so far; upstream also counts compaction summary requests and permission reviews. A missing or damaged sidecar resumes as incomplete usage with one gap, and an unsafe one refuses the resume, as upstream does. Sessions oh-fx saved before it wrote the sidecar resume with incomplete usage, as upstream resumes a session without one. oh-fx writes no usage recovery markers yet either, so a report has no unpublished session usage to fold in, where upstream's adds the usage of the sessions marked in `~/.fx/usage-recovery`.
- Codex responses settle with exact usage as upstream's do: model `codex/<model>`, cost 0, and the response id hashed into a `gen_` id. A custom connection whose stream reports prompt and completion tokens settles exactly too, as `<connection id>/<model>` with cost 0, its cached prompt tokens as cache reads and its reasoning tokens, where upstream counts no usage from custom connections and marks each of their requests as possibly billed, which leaves the session's billing incomplete. Its id is the stream's `id` hashed with the connection's binding, or a random one when the stream has none. A response that ends in a provider failure, a length cut-off or a content filter is an error in oh-fx before its usage is read, so it settles as an ambiguous delivery where upstream records its exact usage.
- Exact records wait in the session's publication backlog with billing pending, as upstream's do until its profile publisher takes them, and oh-fx does not publish them to the profile ledger yet. Nothing reaches the ledger, so `oh-fx usage` reports that tracking has not started unless a ledger is already there, and once 16 records wait, each later request marks the session's billing incomplete, as upstream does at that limit.
