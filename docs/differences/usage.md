# Usage

- The profile usage ledger is `$XDG_DATA_HOME/oh-fx/usage.jsonl`, locked through `usage.lock` beside it, where upstream keeps `~/.fx/usage.jsonl` and `~/.fx/usage.lock`. Its records are upstream's byte for byte, so a ledger fx wrote reads the same in oh-fx. `oh-fx usage` reads only oh-fx's ledger and never fx's, as upstream reads only its own profile.
- A session's `usage-v2.json` counts each provider request as upstream counts it: the request is saved when it starts and when it settles, with its API and wall time, and committed edits add their lines. A subagent's requests count in its parent session's usage, as upstream's do. Only agent model requests are counted so far; upstream also counts compaction summary requests and permission reviews. A missing or damaged sidecar resumes as incomplete usage with one gap, and an unsafe one refuses the resume, as upstream does. Sessions oh-fx saved before it wrote the sidecar resume with incomplete usage, as upstream resumes a session without one. A session whose usage the ledger does not hold yet is marked in `usage-recovery/<session id>` beside `usage.jsonl` before that checkpoint is written, and unmarked after a checkpoint that owes the ledger nothing, as upstream marks `~/.fx/usage-recovery`, and `oh-fx usage` folds the unpublished records, pending generations and gaps of the marked sessions into its report. Sessions saved by upstream's sessions v2 keep their own markers, which oh-fx does not read. Unlike upstream, two cases heal instead of leaving every later report incomplete. A marker's staged copy left by an interrupted write (`.<id>.tmp.<hex>`) is skipped when the markers are listed and removed by that session's next marker write. Discarding a pristine session also removes its marker. A marker whose session directory is missing still makes the recovery unknown, as upstream's does, because an import refresh moves a session aside while it publishes the replacement and may move it back.
- Codex responses settle with exact usage as upstream's do: model `codex/<model>`, cost 0, and the response id hashed into a `gen_` id. A custom connection whose stream reports prompt and completion tokens settles exactly too, as `<connection id>/<model>` with cost 0, its cached prompt tokens as cache reads and its reasoning tokens, where upstream counts no usage from custom connections and marks each of their requests as possibly billed, which leaves the session's billing incomplete. Its id is the stream's `id` hashed with the connection's binding, or a random one when the stream has none. A response that ends in a provider failure, a length cut-off or a content filter is an error in oh-fx before its usage is read, so it settles as an ambiguous delivery where upstream records its exact usage.
- A session publishes its usage to the profile ledger as upstream does. Each settled request starts a background drain that appends the session's pending markers, incidents and exact records under the ledger lock, and each record the ledger accepts then counts in the session's totals and model rows. A session drains once more before it closes. The interactive shell abandons the ledger lock at exit, as upstream's does, so exit never waits for another process, and whatever is unpublished stays in the session's `usage-v2.json` for its next resume. The ledger is compacted as upstream's is: records older than 35 days, and pending markers whose record arrived, are dropped before an append that would pass 32 MiB or 200,000 records, and after an append past 8 MiB once records are a day past that window. Two details differ from upstream's compaction. It rewrites from a fresh read of the ledger under the lock, and a cached index is reused only while the ledger is the same file (its device and inode), so a peer's replacement of equal length and tail is never mistaken for the cached records. It writes the incident of a conflicting pending marker only when the rewrite drops one of its two markers, by expiry or because a record resolved them, since reading both markers back derives it again; upstream writes it every time, so each compaction adds another copy. It also keeps the ledger as it is when the rewrite would not fit the record and size limits. Subagent sessions publish nothing of their own, since their usage counts in the parent session.
- `/usage` and `/cost` open the usage dashboard as upstream's do. One background load serves the 30-day, 7-day and 24-hour scopes and stays cached, and the session scope reads the live session's usage, or a fresh session before the first prompt. Two details differ. The shell asks the controller for each scope, and a finished load sends the report for the scope the menu shows, where upstream's shell polls the load. A scope whose load cannot start, because the profile directory is unavailable, shows "Usage unavailable · press r to retry" where upstream's tab and arrow keys leave it loading. The status row reads "Local oh-fx activity". The shell ignores a late answer for a scope it has already moved past, since its requests are answered asynchronously. Closing the shell abandons a dashboard load still waiting on another process's ledger lock, where upstream's dashboard waits for its loader to finish.
