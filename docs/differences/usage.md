# Usage

- The profile usage ledger is `$XDG_DATA_HOME/oh-fx/usage.jsonl`, locked through `usage.lock` beside it, where upstream keeps `~/.fx/usage.jsonl` and `~/.fx/usage.lock`. Its records are upstream's byte for byte, so a ledger fx wrote reads the same in oh-fx. `oh-fx usage` reads only oh-fx's ledger and never fx's, as upstream reads only its own profile.
- A session's `usage-v2.json` counts each provider request as upstream counts it: the request is saved when it starts and when it settles, with its API and wall time, and committed edits add their lines. A subagent's requests count in its parent session's usage, as upstream's do. Only agent model requests are counted so far; upstream also counts compaction summary requests and permission reviews. No provider reports exact token usage to it yet, so every completed request marks the session's billing incomplete, as upstream marks a request from a provider without exact usage, and nothing reaches the profile ledger, so `oh-fx usage` reports that tracking has not started unless a ledger is already there. A missing or damaged sidecar resumes as incomplete usage with one gap, and an unsafe one refuses the resume, as upstream does. Sessions oh-fx saved before it wrote the sidecar resume with incomplete usage, as upstream resumes a session without one. oh-fx writes no usage recovery markers yet either, so a report has no unpublished session usage to fold in, where upstream's adds the usage of the sessions marked in `~/.fx/usage-recovery`.
